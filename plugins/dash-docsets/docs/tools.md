# Tools — tali-dash-docsets

Generated by `scripts/gen-tool-docs.mjs` from the tool definitions; do not edit by hand. 3 tools.

## `dash_list_docsets`

List the documentation sets installed in Dash (the macOS docs browser) with the KEY to use in dash_search's docsets parameter (e.g. numpy, pytorch, nlab, html, rust). Cheap (~2 kB); call it when unsure which docsets exist or how one is keyed.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `filter` | string | no | Case-insensitive substring over key, name and platform (e.g. "py"). |

**Returns:** `{ total, filter, docsets[{ key, name, platform, identifier, fullTextSearch }] }` rendered as `key  name` lines

**Implementation:** Always refreshes from `GET /docsets/list` (the other tools use a cached copy, `docsetCacheSeconds`). Keys are derived in `docsets.mjs`: the docset `platform` (Dash's own search keyword) unless it is a generic kind (`crate`, `github`, `manPages`, `usercontrib*`, `docgen*`), then the versionless display name; collisions fall back to name, then name + identifier. Identifiers are shown in the canonical value only.

## `dash_search`

Search the docsets installed in Dash. Matches SYMBOL AND SECTION NAMES (classes, functions, methods, guide/section titles, nLab entries) fuzzily — not body text — so query with an identifier or a short title ("Tensor.view", "argsort", "adjoint functor", "<dialog>"), not a sentence. Default: all installed docsets; narrow with docsets (keys from dash_list_docsets; names like "torch" or "PyTorch" also resolve). Each result carries a url for dash_get_page.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `query` | string | yes | Symbol or title to look up. Multi-word queries match titles containing the words; fewer words match more. |
| `docsets` | string[] | no | Docset keys/names to search (e.g. ["numpy", "pytorch"]). Omit for all installed docsets. |
| `types` | string[] | no | Keep only these result types, case-insensitive (e.g. ["Method", "Function", "Class"]; others include Guide, Section, Attribute, Module, Entry, Element, Property, Macro, Type, Word). |
| `maxResults` | number | no | Maximum results to return (default 20, max 200). |
| `snippets` | boolean | no | Also search the user's personal Dash code snippets (default false). |

**Returns:** `{ query, docsets[], allDocsets, types, maxResults, matched, truncated, message, warnings[], results[{ docset, name, type, alsoTypes[], description, url, platform, language, tags }] }` rendered as numbered `docset · type · name — parent` lines each followed by the url

**Implementation:** Resolves `docsets` to identifiers (key, exact name, platform, identifier, or a unique fragment — `"torch"` → PyTorch; ambiguity is an error listing the candidates), then `GET /search`. Over-fetches (2× / 4× with `types`, min 30 / 60, max 1000) because rows are filtered by type and grouped by page afterwards: a symbol row (Method, Function, …) absorbs the Guide/Section/Entry rows of the same page and lists them as `(also …)`. Dash searches names fuzzily; rows typed `Full-Text Search` appear for some docsets when the name search finds nothing (not reliable). A 400 "Docset with identifier … not found" drops the docset cache so the next call re-resolves.

## `dash_get_page`

Read a documentation page from Dash as Markdown, given a url from dash_search (or a link found in a previously read page). Default scope: the SECTION the url's #anchor points at (e.g. one method's signature and description), else the page's main content. section: "page" reads the whole page, "outline" lists its headings with the section values that select them (use it first on big pages), or pass a heading id ("#loc-3"), heading text ("Definition"), or a CSS selector. Output beyond 60000 chars is truncated and the full text saved to a file (path reported). MathML/KaTeX math becomes $LaTeX$; links stay absolute so they can be passed back to this tool.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `url` | string | yes | Page URL from dash_search (http://127.0.0.1:<port>/Dash/…), optionally with #anchor. |
| `section` | string | no | "page" (whole page), "outline" (headings only), "#id" / "id", heading text, or a CSS selector. Default: the url's anchor, else the main content. |
| `format` | "markdown" \| "html" | no | markdown (default) or the cleaned HTML of the selected region. |
| `maxChars` | number | no | Truncate the returned content at this many characters (default 60000); the full text is always saved to a file when truncated. |

**Returns:** `{ url, title, format, scope{ kind: anchor|section|page|outline, target, label?, chars }, pageChars, notes[], outline?, content, truncated?, totalChars?, fullTextPath? }` rendered with a Title/URL/Scope header (plus NOTEs) and the content

**Implementation:** Loopback URLs only (the docset file server Dash runs on a second per-launch port). Pipeline (`html-to-md.mjs`): parse with linkedom → strip chrome (`script/style/nav/aside/footer`, roles navigation/banner/contentinfo, `.headerlink`, breadcrumbs, `aria-hidden`) → select ONE region: explicit `section` (`page`, `outline`, `#id`/`id`/`<a name>`, CSS selector, or heading text with numbering ignored) else the URL anchor (`#id`, `#//apple_ref/…` `<a name>` anchors, `#//dash_ref_<id>/…`) else the main landmark when it holds ≥ 60 % of the text. A heading extends to the next heading of the same or a higher level; a `dt` takes its `dl`; a bare header anchor (rustdoc) grows into its enclosing container until it has text. Links are resolved to absolute URLs; SVG/img become `[diagram]`/`[image: alt]`; turndown (GFM tables) renders with rules for `<pre>` language classes, MathML/KaTeX (`annotation` TeX preferred, Unicode math letters folded to `\mathcal` etc.), Sphinx signatures and field lists, admonitions. Over `maxChars` the content is cut and the full text written to `$TMPDIR/dsh-dash-page-*.md`.
